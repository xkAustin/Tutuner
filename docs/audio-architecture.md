# 音频与调度架构

## 调音器链路

```text
系统麦克风
  → record（PCM16、单声道、48 kHz）
  → PCM 浮点归一化与 8192 样本滑动帧
  → Flutter compute Isolate
  → RMS 噪声门
  → YIN 差分函数与累积均值归一化
  → 60–1400 Hz / 置信度过滤
  → 中值窗口、指数平滑与八度抑制
  → 12-TET 吉他目标或 24-TET 最近音
  → 最多约 20 Hz UI 更新
```

DSP 不依赖麦克风插件，单元测试直接输入合成正弦采样。8192 样本帧保证 E2（82.41 Hz）有足够周期数；2048 样本 hop 保持响应连续。分析与 UI 更新频率分离，计算发生在 Isolate，不阻塞 Flutter UI 线程。

`record` 的录音状态、Flutter 生命周期和 `audio_session` 中断流共同处理来电、后台和设备断开。每次开始或停止都会生成新的录音会话世代，启动、停止和释放操作按顺序执行；监听器、等待中的启动和 Isolate 结果必须匹配当前世代才能更新状态。所有非 `resumed` 生命周期状态都会作废当前会话，因此恢复后只能创建新的音频流与平滑窗口，不复用已过期采样。

## 节拍器链路

经典、木质、电子三套音色各包含重音、普通拍和细分拍，共九个 48 kHz、16-bit PCM WAV。它们在首次播放前一次性加载到 SoLoud；运行期间不读取文件，也不为每拍创建播放器。

`BeatTimeline` 使用单调 `Stopwatch` 的固定起点计算每个事件的绝对理论时间：

```text
due(n) = anchor + round(n × 60,000,000 / BPM / subdivisions)
```

播放侧使用一次性计时器唤醒，并在回调中再次对照单调时钟；它不使用 `Timer.periodic` 驱动音频，也不从“上一拍实际完成时间”推算下一拍，因此不会累计延迟。应用恢复或回调严重迟到时，直接跳到当前时间之后的第一个理论事件，不补播错过的节拍。BPM、拍号、细分或重音变化后从新的合理边界重新建立时间线。

暂停会保留 `_nextEventIndex` 与当前视觉拍位，继续时把这个下一事件重新锚定到当前单调时间之后；停止会清空时间线、事件序号和视觉拍位。因此暂停/继续保持小节进度，停止后的下一次开始固定从第一拍进入。

Tap Tempo 记录最近七个合法点击间隔，用中位数剔除明显异常值，再按新近程度加权求 BPM。小于 180 ms 的误双击被忽略，超过 2 秒的间隔会开始新序列，第一下只建立起点、第二下才产生 BPM。

SoLoud 以低延迟模式、48 kHz、256 帧缓冲运行。当前统一 Dart 接口可以替换成平台原生的未来时间音频队列；本版本没有声称 Dart 调用到硬件输出具备采样级确定性。若物理设备测量显示某个平台的起音抖动超过产品阈值，应保留时间线和控制器，只替换该平台的 `AudioOutputService` 实现。

## 分层

- `core/audio`：输入、输出、会话抽象及插件实现
- `core/dsp`：纯 Dart 音高检测与滤波
- `core/music`：音名、频率、temperament、调弦数据
- `core/metronome`：纯时间线、拍号、Tap Tempo
- `features/*/domain`：可观察状态与业务协调
- `features/*/presentation`：响应式 Material 3 界面
- `core/settings`：异步本地键值持久化
